### Step 6 — captions.html rendering bug (found via QC snapshot, fixed)
- npx hyperframes check flagged widespread text_occluded errors across many timestamps (13.1s, 39.29s, 65.49s, 91.68s, 117.88s, 144.08s, 170.27s, 196.47s, 222.66s) — captured a real snapshot at t=13.1s and confirmed visually: caption text rendered as garbled overlapping fragments ("married couple," overlapping faint ghost text from an earlier/different caption group), not the clean single caption expected.
- Root cause: captions.mjs's generated timeline (404 caption-group divs, one shared GSAP timeline) relies purely on each group's own tween sequence (fromTo at g.start, to-opacity-0 at g.end, hard-kill set at g.end+0.12) with no explicit baseline state at t=0 — when the render/snapshot engine seeks DIRECTLY to a timestamp (not playing sequentially from 0), GSAP's resolution of which prior tween last touched a given element's visibility/opacity was producing a stale/incorrect state for some elements, causing ghost text to bleed through.
- Fix: patched compositions/captions.html (generated output, edited directly since this is a per-project artifact, not the shared skill script) to add `gsap.set(el, {opacity:0, visibility:"hidden"})` immediately on element creation (a hard, unambiguous starting baseline) plus `tl.set(el, {visibility:"visible"}, g.start)` right before each group's own fromTo — giving every element an explicit, seek-safe visible/hidden toggle instead of relying solely on opacity tweens. Verified via repeated snapshot at t=13.1s: ghost text is gone, only the correct single caption group renders.
- Note: this same class of bug likely exists in every other project using the shared faceless-explainer/scripts/captions.mjs — worth reporting upstream, but out of scope to patch the shared script for this run (fixed locally in this project's own generated captions.html instead, consistent with "captions are generated per-project output" — this file would be fully regenerated, wiping the fix, only if captions.mjs build re-runs on this project again).
